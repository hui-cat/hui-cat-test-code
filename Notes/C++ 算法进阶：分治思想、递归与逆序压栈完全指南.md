

> **核心背景**：从汉诺塔问题出发，打通从“人类宏观分治思维”到“计算机底层栈帧模拟”的完整逻辑链路。
> **适用场景**：OJ 复杂递归题、防爆栈优化、Unity 游戏 AI 行为树与寻路算法底层原理。

## 一、 分治思想（Divide and Conquer）

### 1. 核心概念
分治，即“分而治之”。将一个大问题分解成若干个规模较小的相同问题，递归地解决这些子问题，然后将子问题的解合并，从而得到原问题的解。

### 2. 三大步骤
1. **分解（Divide）**：将原问题分解为若干个规模较小、相互独立、与原问题形式相同的子问题。
2. **解决（Conquer）**：若子问题规模较小且容易被解决，则直接解决；否则，递归地求解各子问题。
3. **合并（Merge）**：将各个子问题的解合并为原问题的解。

### 3. 经典应用场景
*   **汉诺塔（Hanoi Tower）**：将 `n` 个盘子的任务，拆解为两个 `n-1` 的任务和一个最大盘移动的任务。
*   **归并排序（Merge Sort）**：将数组一分为二，分别排序，再合并。
*   **快速排序（Quick Sort）**：选基准值，将数组分为小于基准和大于基准两部分，分别递归排序。
*   **二分查找（Binary Search）**：每次将搜索区间缩小一半。

## 二、 递归（Recursion）

### 1. 核心概念
递归是分治思想在代码层面的直接体现。函数直接或间接地调用自身。

### 2. 递归的两大核心要素
*   **递归出口（终止条件）**：必须有，否则会导致无限递归，引发栈溢出（Stack Overflow）。例如汉诺塔中的 `if (n == 1) return;`。
*   **递推关系（状态转移）**：将大问题转化为小问题的公式。例如汉诺塔中的 `H(n) = H(n-1) + 1 + H(n-1)`。

### 3. 递归的底层机制：函数调用栈（Call Stack）
操作系统为每个线程分配一块栈内存。每次函数调用，系统都会在栈上压入一个**栈帧（Stack Frame）**，包含：
*   函数的参数（`from`, `aux`, `to`, `n`）
*   函数的局部变量
*   函数执行到的位置（程序计数器 PC，用来记录“回来之后接着从哪行代码执行”）

当函数返回时，栈帧弹出，控制权交还给上层函数。

### 4. 递归的优缺点
*   **优点**：代码极其简洁，符合人类宏观思维，可读性强。
*   **缺点**：存在“爆栈”风险（系统栈内存通常只有几 MB），函数调用有额外的时间和空间开销，性能略低于纯迭代。

## 三、 逆序压栈（从递归到迭代）

### 1. 为什么需要逆序压栈？
因为**栈是后进先出（LIFO）的，而代码的执行顺序是顺序执行的**。
如果你把任务按执行顺序压栈，最先执行的会被压在栈底，最后才执行。
所以，我们压栈的顺序，必须和期望的执行顺序**完全相反**。

### 2. 核心法则
*   **最先执行的任务，最后压入栈。**
*   **最后执行的任务，最先压入栈。**

### 3. 汉诺塔实战（任务分治型递归转栈）
以汉诺塔为例，期望的执行顺序是：
1. `H(n-1, from, to, aux)` （第一步）
2. `Move(n, from, to)` （第二步）
3. `H(n-1, aux, from, to)` （第三步）

**逆序压栈法则**：压入第三步 -> 压入第二步 -> 压入第一步。

```cpp
struct Task {
    int n;
    char from, aux, to;
    bool isMove; // 标记是“移动盘子”还是“汉诺塔子任务”
};

stack<Task> stk;
stk.push({n, a, b, c, false});

while (!stk.empty()) {
    Task top = stk.top();
    stk.pop();

    if (top.isMove) {
        cout << top.from << "->" << top.n << "->" << top.to << endl;
    } else {
        if (top.n == 1) {
            cout << top.from << "->" << top.n << "->" << top.to << endl;
        } else {
            // 逆序压栈（注意：这里对应的是递归函数的调用顺序）
            stk.push({top.n - 1, top.aux, top.from, top.to, false}); // 第三步
            stk.push({top.n, top.from, top.aux, top.to, true});        // 第二步
            stk.push({top.n - 1, top.from, top.to, top.aux, false}); // 第一步
        }
    }
}
```

## 四、 进阶通用模板：状态机 + 栈帧

当递归调用结束后，还需要回来继续执行代码（例如二叉树遍历，处理完左子树还要回来处理右子树），简单的逆序压栈就不够用了。我们需要在栈帧中加入**阶段标志（Stage）**，模拟程序的执行进度。

### 二叉树中序遍历（左-根-右）的栈模拟

```cpp
struct Frame {
    TreeNode* node;
    int stage; // 0: 待处理左子树, 1: 待处理根节点, 2: 待处理右子树
};

void inorderTraversal(TreeNode* root) {
    stack<Frame> stk;
    stk.push({root, 0});
    
    while (!stk.empty()) {
        Frame& top = stk.top(); // 必须用引用，因为我们要修改 stage！
        
        if (top.node == nullptr) {
            stk.pop();
            continue;
        }
        
        if (top.stage == 0) {
            top.stage = 1; // 修改状态，记录“左子树已处理”
            stk.push({top.node->left, 0}); // 压入左子树任务
        } 
        else if (top.stage == 1) {
            cout << top.node->val << " "; // 执行中间操作
            top.stage = 2; // 修改状态，记录“根节点已处理”
            stk.push({top.node->right, 0}); // 压入右子树任务
        } 
        else {
            stk.pop(); // 左右都处理完了，彻底弹出
        }
    }
}
```

## 五、 实战经验与避坑指南

1.  **变量作用域陷阱**：在手写栈模拟时，极易犯 `if (n == 1)` 而不是 `if (top.n == 1)` 的错误。始终使用明确的局部变量名（如 `curN`），避免全局变量污染。
2.  **空任务不可入栈**：汉诺塔中的 `n=0` 代表“没有盘子需要移动”。任何递归/栈模拟，空任务应该被直接忽略，不能继续塞进栈里。
3.  **输出格式严格校验**：OJ 是严格字符串比对，`a->3->b` 多一个空格、多一个换行都是 0 分。大量输出时务必加 `ios::sync_with_stdio(false); cin.tie(0);`。
4.  **整数除法陷阱**：遇到向下取整公式，尽量用 `int` 的整数除法（自动截断小数），避免用 `double` 配合 `floor` 引入精度误差。
5.  **浮点数输出陷阱**：题目样例输出 `0`，就不能写 `0.0`。用 `if (val == 0) cout << 0;` 特殊处理，其他情况用 `fixed << setprecision(1)`。

## 六、 结合 Unity 游戏开发的进阶思考
*   **行为树（Behavior Tree）**：游戏 AI 的核心架构，底层就是一个状态机驱动的树状分治结构。
*   **A* 寻路算法**：OpenList 和 ClosedList 本质上是优先队列和哈希表的结合，其节点扩展过程也是图搜索中的分治。
*   **多线程 Job System**：在 Unity DOTS 或 C# 的 Job System 中，子线程不允许阻塞式递归。此时必须将算法改造成“迭代 + 显式栈/队列”的形式。

**一句话总结**：分治是思想，递归是语法，逆序压栈是把思想从“系统自动管理”转化为“程序员手动管理”的底层魔法。掌握它，你的算法掌控力将跨越一个维度。
