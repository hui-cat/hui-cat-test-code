对于 C++ 初学者来说，迭代器（Iterator）是一个比较抽象的概念。很多人刚开始刷 OJ 时，只敢用 `v[i]` 这种下标访问，遇到 `sort`、`max_element` 这些必须传迭代器的函数就一头雾水。

其实，**迭代器就是“广义的指针”**。它相当于容器和算法（如 `sort`、`find`）之间沟通的**桥梁**。你今天能用 `sort(v.begin(), v.end())`，正是因为迭代器把容器的位置信息传递给了排序算法。

我为你整理了一份**《C++ 迭代器完全指南》**，结合了你最近遇到的所有 OJ 问题，包含了你最关心的“如何转下标”！

---


> **核心概念**：迭代器是遍历容器（`vector`、`string`、`map` 等）的通用工具。它像指针一样，支持 `*` 解引用、`++` 移动、`==` 比较。
> **核心优势**：让算法（如 `sort`）与具体容器解耦，一套算法可以作用于所有容器。

## 一、 迭代器的基本获取与遍历

每种 STL 容器都提供了获取迭代器的成员函数：
*   `begin()`：指向容器**第一个元素**的位置。
*   `end()`：指向容器**最后一个元素的下一个位置**（这是一个“虚位”，绝不能解引用）。
*   `rbegin()` / `rend()`：反向迭代器，从尾部向头部遍历。

### 1. 传统遍历写法（⭐ 推荐掌握）
```cpp
vector<int> v = {10, 20, 30, 40};

// 获取起始迭代器
auto it = v.begin();

// 遍历：it != v.end() 是终止条件
while (it != v.end()) {
    cout << *it << " "; // *it 解引用，获取当前元素的值
    it++;               // 迭代器向后移动一位（指向下一个元素）
}
// 输出: 10 20 30 40
```

### 2. 范围 for 循环（C++11 语法糖）
你平时写的 `for (auto& x : v)`，编译器在底层**就是**将其翻译成了迭代器的形式。二者完全等价。

### 3. 修改元素
迭代器不仅可以读，还可以写。通过 `*it` 直接修改容器里的值：
```cpp
for (auto it = v.begin(); it != v.end(); it++) {
    *it = *it * 2; // 把每个元素乘 2
}
```

## 二、 核心痛点：如何将迭代器转换为下标？

在 OJ 中，我们经常用 `max_element`、`lower_bound` 等函数拿到一个迭代器。但题目往往要求输出**下标**，这就需要做转换。

### 1. 正向迭代器转下标公式
**公式：`下标 = 迭代器 - 容器.begin()`**

**原理**：`vector` 和 `string` 的迭代器底层就是指针。两个指针相减，得到的就是它们之间相差的元素个数（即下标）。

**OJ 实例（找最大值及其下标）**：
```cpp
vector<int> v = {5, 2, 8, 1, 9};
auto it = max_element(v.begin(), v.end()); // 拿到最大值所在的迭代器

int max_val = *it;                 // 1. 取值：解引用
int max_index = it - v.begin();    // 2. 转下标：迭代器相减
cout << "最大值: " << max_val << "，下标: " << max_index << endl;
```

### 2. 反向迭代器转下标（易错点）
如果使用了 `v.rbegin()` 和 `v.rend()`，得到的是反向迭代器。它的转换公式比较绕：
**公式：`下标 = v.rend() - 反向迭代器 - 1`** （或者使用 `.base()` 转换，极其容易绕晕，**新手强烈建议避开反向迭代器求下标，改用正向下标循环倒序遍历**）。

## 三、 OJ 高频实战场景

### 场景 1：二分查找 `lower_bound`
`lower_bound` 返回第一个大于等于目标值的迭代器。在 OJ 中，题目往往要求输出这个元素的下标。
```cpp
vector<int> v = {1, 2, 2, 3, 4, 5};
auto it = lower_bound(v.begin(), v.end(), 2); // 找到第一个 2 的位置

if (it != v.end()) {
    int index = it - v.begin(); // 下标 = 1
    cout << "第一个 2 出现在下标: " << index << endl;
}
```

### 场景 2：结合 `sort` 和 `unique` 去重（经典组合）
你之前的文档里写过 `sort + unique` 去重，这里的 `unique` 返回的也是一个迭代器，它标记了“垃圾区”的起点。
```cpp
sort(v.begin(), v.end());
auto new_end = unique(v.begin(), v.end()); // 拿到去重后新末尾的迭代器

// 将新末尾到原末尾的垃圾数据全部删掉
v.erase(new_end, v.end()); 
```

### 场景 3：在遍历中删除元素（⭐ 极易踩坑！）
如果你在 `for` 循环中直接 `v.erase(it)`，会导致**迭代器失效**（后面的元素向前移动，原来的 `it` 变成了野指针）。
**正确写法**：利用 `erase` 返回的**下一个有效迭代器**来更新遍历指针。
```cpp
vector<int> v = {1, 2, 3, 2, 4, 2};
// 删除所有值为 2 的元素
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 2) {
        it = v.erase(it); // ⭐ erase 返回下一个元素的迭代器，直接赋给 it
    } else {
        it++; // 只有不删除时才向后移动
    }
}
```

## 四、 ⚠️ 避坑指南与性能建议

1. **`end()` 不可解引用**：`*v.end()` 是未定义行为，会直接导致程序崩溃（RE）。遍历条件永远是 `it != v.end()`，绝不能写 `it <= v.end()`。
2. **`size()` 和 `int` 的选择**：如果你使用下标遍历，一定要用 `int` 而不是 `size_t`。
   ```cpp
   // ❌ 错误：size_t 是无符号整数，当 i 减到 -1 时会变成极大的正数，导致死循环越界
   for (size_t i = v.size() - 1; i >= 0; i--) 
   
   // ✅ 正确：使用 int
   for (int i = (int)v.size() - 1; i >= 0; i--)
   ```
3. **迭代器失效（Iterator Invalidation）**：
   * 当 `vector` 触发扩容（`size == capacity` 时 `push_back`），内存会被重新分配，**之前所有的迭代器全部失效**。绝对不要在遍历中 `push_back`。
   * 当使用 `erase` 删除元素时，被删元素及其之后的迭代器全部失效。
4. **迭代器不是万能的**：`vector` 和 `string` 的迭代器支持 `it + 3`、`it1 - it2`（随机访问）。但像 `list`（链表）或 `map` 的迭代器只支持 `it++`，不支持 `it + 3`，也不支持相减。不过 OJ 初期你只会用到 `vector` 和 `string`，完全不必担心这个限制。

## 五、 结合你的 Unity 目标

在 Unity 的 C# 开发中，虽然没有 C++ 这种“指针式”的迭代器，但 C# 的 **`IEnumerator`** 和 **`foreach`** 底层逻辑完全一致。当你需要写**对象池**（Object Pool）遍历并移除失效对象时，C# 中同样面临“不能在 `foreach` 中直接 `Remove`”的陷阱（会抛出 `InvalidOperationException`），解决方案也是先找出要删除的索引，遍历结束后再统一删除，或者使用 `for` 循环倒序遍历。

**一句话总结**：迭代器是算法与容器之间的桥梁。`begin()` 到 `end()` 是左闭右开区间。转下标记住 `it - v.begin()`，遍历中删元素记住用 `it = v.erase(it)`。
