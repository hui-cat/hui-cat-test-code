

> **题目核心**：根据排名计算赋分 $s = \lfloor 100 \times \frac{n-x}{n} \rfloor$，再根据赋分映射为德育分，按**原始输入顺序**输出。这道题是一道极其经典的“细节杀”题目。算法逻辑不难，但 OJ 的严格评测极其考验边界处理和格式控制。

## 一、 核心避坑点（血泪经验总结）

### 1. 浮点数精度陷阱（⭐ 致命）
*   **错误做法**：使用 `double` 计算，并用 `floor()` 向下取整。例如：`floor(100.0 * ((n - rank) / n))`。由于计算机底层浮点数的精度误差，理论上该得 40 分的同学，可能会计算出 `39.9999999`，`floor` 后变成 39，导致掉入下一个分数段。
*   **正确做法**：题目要求向下取整，且数据均为整数，**绝对不要用浮点数**。利用 C++ 整数除法自动截断的特性：
    ```cpp
    int s = 100 * (n - rank) / n; // 完美向下取整，绝无误差
    ```

### 2. 边界特判：原始得分为 0（⭐ 极易遗漏）
*   **题目规定**：“特殊的，若某位同学得分为 0 分，他将获得 0 分德育分。”
*   **错误做法**：直接计算赋分。如果原始分为 0，通常排名靠后，算出来的 $s$ 大概率是 0，会掉入 `0 <= s < 10` 的区间从而错误地获得 0.2 分。
*   **正确做法**：在计算赋分前，必须先特判原始分数：
    ```cpp
    if (i.score == 0) { deyu = 0.0; continue; }
    ```

### 3. 区间映射：$s=0$ 的归属漏洞（⭐ 致命）
*   **题目表格**：`0.2` 对应 `0 <= s < 10`。
*   **错误做法**：写代码时只写了 `else if (s > 0)`。如果某位同学原始分不为 0，但排名垫底（如 n=10, rank=10），算出的 $s=0$。此时 `s > 0` 为 false，导致该同学**没有被匹配到任何分数段**，在 map 中查不到，输出默认的 `0.0`。
*   **正确做法**：区间映射的最后一步，一定要用 `else` 兜底，或者显式写出 `else if (s >= 0)`。
    ```cpp
    else if (s >= 10) deyu = 0.3;
    else deyu = 0.2; // 涵盖 0 <= s < 10
    ```

### 4. 输出格式：0 与 0.0 的严格比对（⭐ 致命）
*   **题目样例**：0 分输出 `0`，其他分数输出 `0.5`。
*   **错误做法 1**：直接 `cout << deyu << endl;`（会输出 `0.500000`，格式错误）。
*   **错误做法 2**：统一使用 `cout << fixed << setprecision(1) << deyu << endl;`（会把 0 输出成 `0.0`，不符合样例，OJ 判 WA）。
*   **正确做法**：输出时额外判断。
    ```cpp
    if (deyu == 0.0) cout << 0 << endl; // 0分特殊处理
    else cout << fixed << setprecision(1) << deyu << endl; // 其他保留1位小数
    ```

### 5. 并列排名与按原序输出（⭐ 逻辑陷阱）
*   **并列排名**：分数相同时并列（例如 1, 2, 2, 4）。
    ```cpp
    if (i > 0 && stuCpy[i].score == stuCpy[i - 1].score) {
        stuCpy[i].rank = stuCpy[i - 1].rank;
        continue;
    }
    stuCpy[i].rank = i + 1;
    ```
*   **按原序输出**：题目要求“按输入名单的顺序依次输出”。
    *   策略：拷贝一份数组 `stuCpy` 用于排序和计算，原数组 `Students` 保持原样。利用 `unordered_map<string, double>` 记录名字到最终德育分的映射，最后遍历原数组输出。

## 二、 通用 OJ 实战心得（举一反三）

1.  **看到取整符号就条件反射想整数运算**：题目只要出现 $\lfloor \dots \rfloor$ 或 `向下取整`，并且数据是整数，坚决用 `int` 或者 `long long` 来算，不要碰 `double`。
2.  **边界特判是第一生产力**：每次写完主体逻辑，都要问自己：“如果数据是 0、如果是 1、如果是空、如果是最大值，代码还能跑对吗？”
3.  **OJ 是严格的字符串比对**：输出格式必须和样例**像素级一致**。多一个空格、多一个换行、多一个小数点，都是 0 分。
4.  **算法题不只有算法**：这道题同时考察了“结构体排序”、“自定义比较函数”、“哈希映射”、“数值计算”、“边界处理”、“格式输出”。能把这种题做对，说明你的基础非常扎实。

## 三、 核心逻辑框架速查（代码模板）

```cpp
// 1. 特判 0 分
if (原始分 == 0) {
    德育分 = 0.0;
    map.insert({名字, 德育分});
    continue;
}

// 2. 整数运算算赋分（自动向下取整）
int s = 100 * (n - rank) / n;

// 3. 区间映射（else 兜底防遗漏）
if (s >= 90) ...
else if (s >= 75) ...
...
else 德育分 = 0.2; // 涵盖 0 <= s < 10

// 4. 输出（0 单独处理）
if (德育分 == 0.0) cout << 0 << endl;
else cout << fixed << setprecision(1) << 德育分 << endl;
```
